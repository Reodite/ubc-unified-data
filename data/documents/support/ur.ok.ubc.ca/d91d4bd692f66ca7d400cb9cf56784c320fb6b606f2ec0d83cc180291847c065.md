-   Accessibility and usability \| Page layouts and components

-   August 20, 2026

Clear headings and a logical page structure help people understand and navigate web content\. They are especially important for people who use screen readers, which can identify headings and page regions and allow users to move directly to the information they need\.

## Use headings to communicate page structure

Headings identify the page and divide content into meaningful sections\. Screen readers can navigate by headings rather than reading the entire page from beginning to end\.

Do not use bold text, large type, colour or other visual formatting to create the appearance of a heading\. Screen readers don’t recognize these when navigating a page\.

Not every piece of prominent text needs to be a heading\. Use headings when the text introduces and describes a section of content\.

### Check headings within Elementor elements

Some Elementor elements, including accordions, tabs, cards and calls to action, may include their own title or heading settings\.

Check that headings within elements:

-   fit logically within the page’s existing heading structure,
-   describe the content they introduce, and
-   remain available when the layout changes between desktop, tablet and mobile devices\.

Avoid using an element simply because its default styling creates the appearance you want\. Choose elements based on the purpose and structure of the content\.

## Keep visual and reading order aligned

Elementor can visually rearrange content using responsive settings or reversed row and column layouts\. These changes may cause the visual order to differ from the order experienced by someone using a screen reader or keyboard\.

Avoid using visual positioning to change the meaning or sequence of content\. When content order matters:

-   add elements and build containers in the intended reading order,
-   allow responsive layouts to stack in that same order,
-   avoid using reverse\-order settings to correct the visual layout, and
-   check that headings remain before the content they introduce\.

Review the structure again after making responsive changes\.

-   Accessibility and usability \| Navigation and menus \| Page layouts and components

-   September 9, 2026

PDFs and other downloadable files can be useful and necessary for provider users with reports, forms, templates, presentations and resources\.

However, whenever possible, provide essential information directly on the page and include downloadable files when the format serves a specific user need\.

## Link to the authoritative source

You should only link to files hosted on the webpage’s domain\. If the file is hosted on another website, you should link to the page where the host website is linking to the file\.

**Linking directly to the file is risky as that link will be broken whenever the file is updated\.** To avoid creating an error for the users, it is safer to link to the webpage\.

Alternatively, uploading the document to your website increases the risk of outdated or conflicting versions appearing across UBCO’s website\.

The same principle applies to files you maintain: wherever possible, maintain one authoritative version and link to it consistently\.

## Consider whether you need a file

Do not create or upload a file simply because the content already exists as a document\.

Use a file when users need to:

-   print or preserve a fixed\-layout document
-   critical information \(dates, requirements, actions\) are not subject to change regularly\*
-   download an official report, publication, plan or policy
-   edit or complete a document offline
-   access a resource that is intentionally distributed in its original format

\* **If information is likely to change regularly**, consider putting the information directly on a webpage\. Files can be downloaded and used after they’ve been updated, running the risk of outdated information continuing to be referenced by users\.

### Choose the right file type

Use a format that supports what users need to do with the content\.

**Note**: Editable documents should not be linked to if users are not meant to update them—these should be added as PDFs\.

#### PDF

Use for final documents where a consistent layout, printing or distribution format is important\.

#### Images \(JPG, PNG\)

Link to images if they are integral to the content and cannot be properly made visual on the page \(e\.g\., posters\)

#### Word \(DOCX\)

Use when users need to edit or adapt a document, such as a template\.

#### Excel \(XLSX\) or CSV

Use for structured data, calculations or information users need to sort, filter or manipulate\.

#### PowerPoint \(PPTX\)

Use when users need the presentation itself for presenting, adapting or reusing slides

## Make files accessible before publishing

Accessibility applies to downloadable content as well as webpages\.

**Before publishing a file:**

-   use proper headings, lists and document structure,
-   provide meaningful alternative text for relevant images,
-   ensure tables have appropriate structure,
-   use descriptive links within the document, and
-   confirm the reading order is logical\.

### Keep file behaviour predictable

Open files in the same browser tab by default\. Do not force a new tab simply because a link leads to a PDF\.

Also avoid assuming that selecting a file link will always trigger a download\. Browsers and devices may display some file types directly\.

Use “View” in the link text when opening the resource is appropriate and “Download” when users are expected to save or edit the file\.

### Manage files as published content

Files can remain accessible through links, bookmarks and search results long after the webpage containing them has changed\. If files should no longer appear publicly, delete them from the website’s Media Library\.

Avoid file names such as final\-v2\-updated\-FINAL\.pdf\. Use a concise, descriptive name that will continue to make sense when the file is downloaded\.
